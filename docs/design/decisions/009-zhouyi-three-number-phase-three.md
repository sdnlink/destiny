# ADR-009：周易三数数字起卦第三阶段基线

> 状态：第三阶段已实现，术数规则待专家签署
> 日期：2026-08-16

## 1. 问题

项目早期周易数字入口使用两个数字：第一数取下卦、第二数取上卦、两数之和取动爻。第三阶段要求建立角色更明确的三数法：第一数只负责上卦、第二数只负责下卦、第三数只负责动爻。

两个算法输入含义不同。直接改写旧`numbers`方法会使历史任务无法复算，因此必须并行版本化，不能用同一个方法名隐藏替换。

## 2. 输入契约

新方法输入恰好三个非负整数：

| 位置 | 角色 |
| --- | --- |
| `number1` | 上卦 |
| `number2` | 下卦 |
| `number3` | 动爻 |

API使用`numbers: [number1, number2, number3]`。布尔值、浮点数、字符串、负数以及非三个元素均拒绝。当前基线不擅自解释负数的术数含义；若未来流派需要，必须新增规则版本。

## 3. 八卦映射

映射不写在起卦函数中，保存在`app/zhouyi/config/hexagram_mapping.py`。默认版本为：

```text
earlier-heaven-number-v1
1乾 2兑 3离 4震 5巽 6坎 7艮 8坤
```

上下卦分别除以8取余，余0归8。映射配置和输入模型均不可变。当前只发布一个待审核映射版本；新增其他流派必须增加独立版本和测试，不能修改现有版本内容。

## 4. 动爻与变卦

第三数除以6取余，余0归6。第三数不与前两个数字求和。六爻仍按初爻至上爻排列，只翻转确定的一个动爻，再由公共卦象核心生成变卦、互卦、错卦和综卦。

该算法不调用时间、随机源、数据库、语料或LLM。

## 5. 版本与接口

- 引擎版本：`zhouyi-three-number-engine-1.0.0`
- 规则版本：`zhouyi-three-number-v1.0.0`
- 映射版本：`earlier-heaven-number-v1`
- 直接接口：`POST /v1/zhouyi/three-numbers`
- 统一接口：`module=zhouyi`、`method=three_numbers`

兼容接口`POST /v1/zhouyi/numbers`继续执行旧双数法。两个方法不得在报告中合并成同一规则。

## 6. 证据链

响应包含原始输入、归一化角色、映射版本、原始余数、余0归一值、上下卦、六爻、动爻、本卦、变卦、五步`calculation_trace`和带规则编号的`steps`。

示例`[23,47,5]`：

```text
23 % 8 = 7 -> 艮为上卦
47 % 8 = 7 -> 艮为下卦
5 % 6 = 5 -> 第5爻动
艮上艮下 -> 艮卦
第5爻变化 -> 渐卦
```

## 7. 测试基线

自动测试覆盖：

- 乾1至坤8全部映射及映射不可变性。
- `[23,47,5]`得到艮之渐。
- `[25,38,3]`得到讼之姤。
- `[0,0,0]`按余0归8、归6得到坤之剥。
- 非三个值、负数、布尔、浮点、字符串和未知映射版本均拒绝。
- 相同输入和版本完整响应一致。
- 直接API、统一API、综合解释和工程验证案例。

这些测试证明代码确定性，不证明该起卦流派已获专家认可。
