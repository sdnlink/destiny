# ADR-002：MVP计算与规则工程基线

> 状态：工程采用，术数内容待专家签署  
> 日期：2026-08-15

## 背景

项目进入公共历法、周易和梅花易数MVP开发。详细计划中的时间边界、起卦方式、综合策略和技术栈尚未形成专家签署结论。为了继续构建可测试的确定性内核，需要选择明确且可替换的工程基线，同时避免把临时选择宣传为唯一流派标准。

## 技术决策

- MVP计算服务使用Python和FastAPI。
- 使用MIT许可的 `lunar-python 1.4.8` 处理公农历、节气、干支和八字基础数据。
- 依赖版本固定在 `backend/requirements.txt`，算法结果记录引擎和规则版本。
- 核心计算函数保持纯函数形式，不访问用户数据库和语言模型。
- AI解释在MVP计算链路中关闭。
- 综合分析首期只做并列对照和冲突展示，不生成自动吉凶总分。

## 时间规则基线

- 年柱：以立春为边界。
- 月柱：以节令为边界。
- 日柱：以子初23:00为换日边界。
- 时区：输入必须显式提供IANA时区。
- 真太阳时：默认关闭；启用时保留原时间、经度、标准经线、经度修正、均时差和修正后时间。
- 历法输入范围由底层库支持范围和标准案例共同限制。

上述规则均作为请求参数或规则版本保存，后续专家确认其他流派时并行增加规则集，不覆盖历史结果。

## 周易基线

- 手工六爻从初爻到上爻输入，允许值为6、7、8、9。
- 6为老阴、7为少阳、8为少阴、9为老阳；6和9为动爻。
- 支持双数起卦：第一数取下卦，第二数取上卦，两数之和取动爻。
- 余数0在八卦中按8处理，在动爻中按6处理。
- 输出本卦、变卦、互卦、错卦和综卦，不在未审核规则下自动生成事项吉凶。

## 梅花易数基线

- 时间起卦的用户输入为公历时间，计算前转换为农历年月日和时支。
- 上卦数：年支序数 + 农历月 + 农历日。
- 下卦数：上卦数 + 时支序数。
- 动爻数：下卦数除以6取余，余0按6。
- 双数起卦：第一数取上卦，第二数取下卦，两数之和取动爻。
- 动爻所在三爻卦为用卦，另一三爻卦为体卦。
- 输出体用五行的生、克、比和关系事实；旺衰、应期和事项断语待专家规则与案例批准后启用。

## 输出边界

计算结果分为：

- `facts`：确定性盘面和时间派生值。
- `steps`：带顺序、输入、输出和规则编号的计算过程。
- `evidence`：体用五行等结构化关系。
- `judgements`：首期为空或只包含已审核规则。
- `warnings`：边界、缺失和专家未审核提示。
- `explanation`：确定性模板对输入、盘面、步骤和关系事实的可读复述，每段保留规则编号。
- `advisory`：用户显式请求时生成的未审核事项检查清单，与正式判断分离。
- `literature`：由本卦和变卦受控词检索得到的书籍原文、来源和自动候选观点。

语料检索结果只能作为专家引用候选，不能自动写入 `judgements`。

`explanation`不等同于`judgements`。在解释规则通过专家审核前，它不得把卦象、体用或五行关系转换成事项吉凶、应期、概率和行动建议。

`advisory`允许把事项类别和体用关系组织成待核实的关注点、通用行动清单和风险问题，但必须标记`unreviewed_engineering_template`、保持`polarity: indeterminate`，不得进入正式综合判断或替代医疗、法律、投资和安全等专业意见。

`literature`只作为内部研究引用。自动匹配必须保留原文、文本块、哈希和来源，并标记`automatic_candidate_unreviewed`。词语命中不等于规则适用，文献观点不得自动升级为正式`judgements`。

## 影响

该决策允许开发和测试确定性事实层，但不表示周易、梅花易数的流派解释已经通过专家审核。专家签署后如果规则发生变化，发布新规则主版本，并用标准案例比较新旧结果。
