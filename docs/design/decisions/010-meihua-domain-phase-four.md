# ADR-010：梅花易数独立领域第四阶段基线

> 状态：第四阶段已实现，术数规则待专家签署
> 日期：2026-08-16

## 1. 目标与边界

梅花易数必须是独立领域，不从周易引擎借数字起卦规则，也不从六爻借世应、纳甲或六亲。本阶段将实现迁入`app/meihua`，只依赖`app/common`的卦象和五行基础事实，以及`app/calendar`的历法事实。`app/core/meihua.py`只保留历史导入兼容，不再承载算法。

## 2. 起卦方法

### 2.1 两数法

- 第一数取上卦，除以8取余，余0归8。
- 第二数取下卦，除以8取余，余0归8。
- 两数之和取动爻，除以6取余，余0归6。

兼容接口为`POST /v1/meihua/numbers`，统一方法为`meihua/numbers`。

### 2.2 三数法

- 第一数独立取上卦。
- 第二数独立取下卦。
- 第三数独立取动爻，不与前两数求和。

新接口为`POST /v1/meihua/three-numbers`，统一方法为`meihua/three_numbers`，规则版本为`meihua-three-number-v1.0.0`。

数字模型只接受严格整数，不把布尔、浮点或字符串自动转换为数字。为保持既有梅花数字入口兼容，当前允许有符号整数并按Python非负余数规则归一；这只是确定性输入口径，不代表负数术数含义已获认可。

### 2.3 时间法

- 年支序数加农历月和农历日作为上卦源数。
- 上卦源数再加时支序数作为下卦源数。
- 下卦源数同时作为动爻源数。
- 闰月按月份绝对值取数，并在结果中警告。

时间法只消费统一历法引擎输出，不自行重复计算节气或四柱。

### 2.4 个体自动法

沿用ADR-006：在年月日源数中加入凭证派生的1至64个体数，再加时支生成下卦和动爻。结果只保留凭证哈希，不回传原始凭证。

## 3. 互卦、变卦与体用

本卦六爻按初爻至上爻排列。互卦由二三四爻构成下互卦、三四五爻构成上互卦。变卦只翻转确定动爻。

体用规则为梅花专属：

- 动爻在1至3爻：下卦为用，上卦为体。
- 动爻在4至6爻：上卦为用，下卦为体。

该体用关系不得转换成六爻世爻、应爻。输出不得包含`host_line`、`response_line`、纳甲或六亲。

## 4. 五行关系

体卦、用卦和变卦之用只计算五行生、克、比和结构事实：体用比和、用生体、体生用、用克体、体克用。关系分别记录本卦阶段和变卦阶段。当前不据此自动生成吉凶、旺衰、应期或现实概率。

## 5. 证据链

每次结果包含原始输入、归一化源数、起卦方法、规则版本、上下卦和动爻取余、本互变错综卦、体用、分阶段五行关系、`calculation_trace`、带规则编号的`steps`及限制。内核不访问LLM、语料库或随机源。

## 6. 测试基线

自动测试覆盖：

- 两数法`[1,2]`得到履卦、第3爻动。
- 三数法`[25,38,5]`得到讼卦、家人互卦、第5爻动、未济变卦。
- 第三数改变体用位置但不改变本卦。
- 余0归8和归6得到坤之剥。
- 有符号整数可复算，布尔、浮点和字符串拒绝。
- 闰月警告、时间法轨迹和个体自动法重放。
- 梅花领域不导入周易、六爻、大六壬或旧`core`实现。
- API、综合解释、规则登记和工程验证案例。
