# ADR-013：阳宅风水方位独立领域第七阶段基线

> 状态：第七阶段方位工程实现完成，术数规则待专家签署
> 日期：2026-08-16

## 1. 目标与边界

本阶段建立`app/fengshui`独立领域，只处理可由测量值确定的罗盘方位事实：角度归一化、磁偏角修正、真北坐向、二十四山和测量误差传播。领域内核不导入历法、周易、梅花、六爻、大六壬或旧`app/core`算法，也不调用语言模型和知识库。

方位事实与流派判断必须分离。本阶段不生成八宅宅卦、命卦、玄空运盘、山盘、向盘、飞星、形势判断、吉凶、应期或行动断语。后续流派必须使用独立规则版本和专家案例，不能把当前山向事实直接包装成判断。

## 2. 输入与坐标口径

- 方位角以正北为`0°`，按顺时针递增，归一化到`[0°, 360°)`。
- `input_reference`只允许`magnetic`或`true`。
- 磁北输入采用`真北角 = 磁北角 + 磁偏角`；真北输入不重复应用磁偏角。
- 坐山为真北向首加`180°`并归一化。
- 角度、磁偏角和误差只接受有限数值，拒绝布尔、字符串数字、NaN和Infinity。
- 测量误差范围为`0°`至`180°`。来源和测量方法可作为元数据记录，不参与隐式推断。

## 3. 二十四山规则

二十四山顺序固定为：子、癸、丑、艮、寅、甲、卯、乙、辰、巽、巳、丙、午、丁、未、坤、申、庚、酉、辛、戌、乾、亥、壬。每山中心间隔`15°`，每个区间宽`15°`并采用左闭右开。

因此子山为`[352.5°, 360°) ∪ [0°, 7.5°)`，癸山为`[7.5°, 22.5°)`；恰好`7.5°`归癸山。二十四山常量作为只读规则放在领域包中，并与`data/generated/fengshui_mountains.jsonl`保持一致。

## 4. 误差传播

输入误差解释为向首角度的正负区间。引擎返回向首和坐山各自的主分类、距最近分界距离、测量区间、全部候选山向和稳定性标志。

误差区间覆盖多个山向时分类不稳定。即使误差未跨界，向首距分界不足`1°`也产生边界预警。预警要求不同位置、不同时段复测，不允许系统擅自选择一个候选作为最终流派输入。

## 5. 协议与接口

领域结果遵守统一事实协议，包含`schema_version`、`system`、引擎与规则版本、原始及归一化输入、`facts`、轨迹、步骤、证据、判断和警告。`judgements`固定为空数组。

独立接口为`POST /v1/fengshui/direction`；统一接口使用`module=fengshui`、`method=direction`。命令行脚本调用同一领域内核，不保留第二套分类算法。Web工作台提供独立风水场景，但不默认加入综合术数推演，因为山向必须来自真实测量。

## 6. 规则与案例

本阶段登记`FS-DIRECTION-NORMALIZE-001`、`FS-DECLINATION-001`、`FS-24MOUNTAIN-001`和`FS-UNCERTAINTY-001`四条草稿规则。

工程案例覆盖真北午向子坐、磁北加偏角后的跨界候选，以及`7.5°`左闭右开边界。自动测试同时覆盖四正山、环绕、坐向相反、严格输入、真北不重复修正、误差候选和领域依赖边界。

## 7. 后续顺序

下一步先设计房屋项目和现场多次测量持久化，再建设户型坐标校准、中宫及九宫覆盖。八宅和玄空分别立项、分别选定流派与案例；在规则签署前继续只展示空间和盘面事实。
