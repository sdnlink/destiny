# ADR-006：个体化自动起卦协议

> 状态：已实现，术数内容待专家签署
> 日期：2026-08-16

## 问题

原自动排盘存在三个混淆：

- 周易、梅花和六爻复制同一套农历时间取数，因此同一次综合推演必然同卦。
- 时间公式只使用时支，同一两小时时辰内所有用户必然同卦。
- 周易默认手工爻值固定，用户不修改时每次结果也固定。

这不是缓存错误，但不适合作为多个独立模块的自动起卦输入。

## 目标

- 不同用户同时起卦时使用彼此独立的起卦凭证。
- 同一凭证可重放，便于审计和案例复核。
- 保留传统纯时间接口，不改写历史结果。
- 允许自然撞卦，不人为承诺100人绝不出现相同卦象。

## 起卦凭证

前端每次新建或重置推演时，使用浏览器密码学随机源生成128位UUID，字段名为 `cast_nonce`。同一次表单重复提交保持凭证不变；新建推演生成新凭证。

后端不使用全局随机状态，而是以 `SHA-256(domain + cast_nonce + sequence)` 派生各模块所需数值。模块使用不同 `domain`，避免同一凭证在不同体系中得到同一数列。结果保留凭证哈希、派生值和规则版本；原始凭证只随输入传递，不在响应中回传。

## 分模块方法

### 周易自动

使用 `zhouyi-auto-coins-v1` 域派生六次三枚铜钱。每枚铜钱取值2或3，每爻三枚相加得到6、7、8、9。六爻从初爻到上爻排列，生成本卦、动爻和变卦。

### 六爻自动

使用 `liuyao-auto-coins-v1` 独立派生六次三枚铜钱，再执行八宫、世应、纳甲、六亲、六神和旬空。它与周易自动不是同源卦；用户明确选择共用一卦时应使用未来的“共享卦盘”工作流，而不是把两次独立结果伪装成相互印证。

### 梅花自动

保留年月日時起例，并使用 `meihua-personal-number-v1` 派生1至64的个体数。个体数加入年月日总数后取上卦，再加时支取下卦和动爻。这是对《梅花易数》“同年月日時可加姓氏笔画等数”案例的工程化扩展，不宣称随机凭证等同于姓名笔画。

### 大六壬自动

使用 `liuren-report-number-v1` 派生1至12的报数，将其映射为占时；实际时支继续保留。该入口属于报数占时工程法，原时间占时接口继续存在。

## 接口

| 体系 | 个体自动接口 | 兼容接口 |
| --- | --- | --- |
| 周易 | `POST /v1/zhouyi/auto` | `/time`、`/manual`、`/numbers` |
| 梅花 | `POST /v1/meihua/auto` | `/time`、`/numbers` |
| 六爻 | `POST /v1/liuyao/auto` | `/time`、`/numbers` |
| 大六壬 | `POST /v1/liuren/auto` | `/time`、`/numbers` |

统一计算接口的方法名为 `auto`，输入包含历法参数和 `cast_nonce`。

## 碰撞边界

六十四卦和6/7/8/9六爻组合都是有限集合。100人独立起卦仍可能自然得到相同本卦，且这不表示两人的现实答案相同。系统通过以下信息区分任务：

- 起卦凭证和完整六爻值。
- 动爻、时间、事项类别和问题摘要。
- 各模块对应解释和现实核实点。

系统不得为了“看起来不同”而篡改自然碰撞结果，也不得把不同模块或不同用户的同卦自动视为相互验证。

## 验证

- 相同凭证、时间和版本必须得到完全相同结果。
- 不同模块使用同一凭证时派生数列必须独立。
- 100个固定测试凭证不得退化成单一或少量固定结果，并报告本卦、完整爻值和报数的唯一值数量。
- 前端必须展示起卦方式和凭证短哈希，避免用户误认为结果只由时间产生。

固定100凭证回归样本当前得到周易97种完整爻值、六爻98种完整爻值、梅花23种“本卦加动爻”组合，六壬覆盖12种报数。该数字用于监测算法退化，不作为概率准确率或生产环境唯一性承诺。
