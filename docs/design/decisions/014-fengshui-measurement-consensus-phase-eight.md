# ADR-014：阳宅多次测量共识第八阶段基线

> 状态：第八阶段工程实现完成，测量阈值待专家签署
> 日期：2026-08-16

## 1. 目标与范围

本阶段在风水独立领域内增加三至十二次现场坐向读数的确定性汇总。每次读数先独立执行角度归一化和磁偏角修正，再计算测量共识；禁止先对磁北原始值做普通算术平均。

本阶段不保存地址、户型或用户身份。房屋档案属于事务及敏感数据，目标架构要求使用具备租户隔离和字段加密的PostgreSQL服务；ClickHouse只能接收脱敏计算明细，不能作为房屋档案的唯一事务库。仓库尚未引入该服务，因此FS-001仍未完成。

## 2. 为什么使用圆周统计

方位角是圆周变量。`359°、0°、1°`的共识方向应为`0°`，普通平均会错误得到`120°`。本阶段以正弦、余弦向量均值计算圆周均值，并返回向量长度作为方向集中度。

同时计算包含全部真北读数的最小圆弧。最小圆弧用于识别读数离散程度，不受0/360度环绕影响。

## 3. 保守误差包络

对每次读数计算其与圆周均值的最短角距离，再加该读数声明的测量误差。所有结果的最大值作为合并测量误差：

```text
effective_error = max(angular_distance(mean, reading_i) + error_i)
```

该区间包含每次读数及其自身误差。随后复用二十四山误差传播规则，返回向首和坐山的全部候选，不通过投票删除边界候选。

## 4. 状态规则

- `consistent`：最小覆盖弧不超过`10°`，圆周均值有效，合并误差不跨二十四山边界。
- `boundary_sensitive`：读数可形成共识，但合并误差覆盖多个山向。
- `inconsistent`：最小覆盖弧超过`10°`，或方向向量相互抵消，不能形成可信共识。

`10°`是工程阈值，不是已发布的传统术数规则。正式使用前必须结合设备规范、现场流程和专家案例签署。`inconsistent`时不得生成伪造的稳定分类；方向完全抵消时`aggregate`明确为`null`。

## 5. 接口与展示

独立接口为`POST /v1/fengshui/measurements`，统一接口使用`module=fengshui`、`method=measurements`。响应保留每次原始输入、真北角、山向、距边界距离、圆周统计、合并误差、步骤和规则编号。

Web工作台支持单次分析与多次共识切换，可增删三至十二个读数。结果页分别展示共识山向、统计质量、候选山向和逐次修正表。任何状态下`judgements`均为空，不生成八宅、玄空或吉凶结论（本 ADR 记录第八阶段时点；后续八宅/玄空已作为独立端点提供确定性事实，仍不生成吉凶断语）。

## 6. 规则与案例

新增`FS-MEASUREMENT-CONSENSUS-001`草稿规则。工程案例覆盖：

1. `359°、0°、1°`跨正北后得到`0°`共识；
2. `6°、8°、10°`形成`8°`均值但误差跨子、癸边界；
3. `0°、120°、240°`方向相互抵消，不生成合并坐向。

下一阶段在PostgreSQL事务边界和敏感字段方案确认后实现房屋项目及测量会话保存，或继续推进不涉及用户持久化的户型几何校准内核。
