# ADR-011：六爻独立领域第五阶段基线

> 状态：第五阶段已实现，术数规则待专家签署
> 日期：2026-08-16

## 1. 目标与边界

六爻必须是独立领域，不借用梅花易数的体用、时间阶段或断法。本阶段将实现迁入`app/liuyao`，只依赖`app/common`的卦象、干支、五行和确定性起卦工具，以及`app/calendar`的历法事实。`app/core/liuyao.py`只保留历史导入兼容，不再承载算法。

六爻内核不调用语言模型、语料检索或随机源。相同输入、时间、时区和规则版本必须得到相同盘面。

## 2. 输入与爻序

六爻统一按初爻至上爻排列，数组第一个元素始终是初爻。该顺序用于输入、归一化结果、卦象六爻、纳甲盘和计算轨迹，不允许在接口层静默倒序。

### 2.1 六爻值录入

`lines`必须恰有六个整数，每个值只能为6、7、8或9：

- 6为老阴，阴爻且动；
- 7为少阳，阳爻且静；
- 8为少阴，阴爻且静；
- 9为老阳，阳爻且动。

接口为`POST /v1/liuyao/lines`，统一方法为`liuyao/lines`。

### 2.2 三枚硬币录入

`coins`必须恰有六轮，每轮必须恰有三个整数，每枚只允许2或3。工程编码约定正面记3、反面记2，每轮求和得到6至9，再按六爻值规则转换；接口不接收含糊的正反面文本，也不推断实体硬币状态。

接口为`POST /v1/liuyao/coins`，统一方法为`liuyao/coins`。结果同时保留六轮原始编码、每轮和值和归一化六爻值。

### 2.3 兼容入口

时间法、双数法和个体自动法继续保留。时间法和双数法是已有工程基线，不冒充传统摇卦；个体自动法按六爻专属派生域生成六轮硬币值，可凭起卦凭证重放，不复用周易自动起卦结果。

## 3. 盘面事实

所有入口使用同一六爻排盘过程，输出：

- 本卦、动爻和变卦；
- 京房八宫归属、宫五行、宫序、世爻和应爻；
- 本卦六爻纳干、纳支、支五行和六亲；
- 按占日天干从初爻顺排的六神；
- 月建、日柱、日支、旬首和旬空；
- 每爻的6/7/8/9值、老少阴阳、动静和变化后阴阳。

以上均为盘面事实。当前不自动生成用神、旺衰、应期、吉凶或事项断语，也不使用梅花体用概念。

## 4. 伏神与飞神覆盖边界

伏神、飞神存在不同取法，当前尚未完成规则选择和标准案例签署。系统不得根据开发者偏好选择排法，也不得生成占位爻位。所有六爻结果固定返回：

```json
{
  "status": "pending_rule_selection",
  "hidden_spirits": [],
  "flying_spirits": [],
  "reason": "伏神飞神取法和标准案例尚未完成规则签署"
}
```

只有在规则登记、来源、专家签署和正反案例同时完成后，才能发布新的规则版本并改变该状态。

## 5. 证据链

每次结果包含原始输入、归一化输入、算法与规则版本、本变卦、完整纳甲盘、`calculation_trace`、带规则编号的`steps`、覆盖状态和限制说明。六爻值与三枚硬币分别使用`LY-LINES-001`和`LY-COINS-001`，伏神飞神边界使用`LY-HIDDEN-FLYING-COVERAGE-001`。

## 6. 测试基线

自动测试覆盖：

- 输入模型不可变，长度、整数类型和值域严格校验；
- `[9,7,7,7,7,7]`得到乾卦、初爻动、变姤卦；
- 六轮硬币`[[3,3,3],[3,2,2]... ]`与上述六爻值结果一致；
- 多动爻及每爻变化后阴阳；
- 64卦均有唯一八宫归属；
- 世应、纳甲、六亲、六神、月建、日辰和旬空；
- 伏神飞神未签署时不生成推测值；
- 自动起卦可重放，完整计算轨迹和规则编号可核验；
- 六爻领域不导入梅花、周易、大六壬或旧`core`算法。

以上均为工程回归，不代表流派专家签署。下一阶段为大六壬独立领域迁移与完整课体覆盖。
