# 015 七步推理工作流的规则登记

- 状态：草案
- 日期：2026-11-04

## 背景

引擎层（历法、周易、梅花、六爻、大六壬、奇门、八字、紫微、风水）每个结果都带 `rule_ids`，
可以直接追溯到 `data/rules/mvp-engineering-baseline.json` 里的条目。
但编排层（`app/workflow`、`app/interaction`）此前没有任何规则登记：
用神怎么取、旺衰怎么判、吉凶等级怎么算、应期怎么推，全部只写在代码里，
文档无法核对、结果无法追溯，也无法复核口径是否与古籍一致。

本决策把编排层的判定口径显式登记为工程规则，并在每一步输出里回填 `rule_ids`。

## 规则清单

| rule_id | 覆盖内容 | 落地位置 |
| --- | --- | --- |
| WF-YONGSHEN-001 | 事项类别 → 六亲用神，以及用神五行的盘面推导 | `app/workflow/steps.py: step3_identify_yongshen`、`_resolve_yongshen_element` |
| WF-WANGSHUAI-001 | 用神相对月令日辰的旺衰（旺/相/休/囚/死） | `app/workflow/steps.py: step4_wangshuai_analysis` |
| WF-FORTUNE-001 | 旺衰与体用关系的吉凶等级口径 | `app/workflow/steps.py: step6_synthesis_judgement` |
| WF-TIMING-001 | 应期窗口（逢值、逢冲、月令节气） | `app/workflow/steps.py: _calculate_timing` |

## 关键口径

### 用神五行只能按盘面推导（WF-YONGSHEN-001）

六亲（父母、兄弟、子孙、妻财、官鬼）的五行随卦宫五行变化，**不存在**固定的「六亲 → 五行」对照表。
此前代码写死了 `官鬼→木、妻财→土、父母→水、子孙→金、兄弟→火`，与纳甲结果系统性冲突。
现行做法：

1. 事项类别先经 `app/common/categories.normalize_category` 归一，再映射六亲用神；
2. 在六爻纳甲爻表里按 `six_relative` 找用神爻，两现时取动爻；
3. 世爻、应爻类用神按 `roles` 匹配；
4. 用神五行取该爻 `element`（由纳甲地支推出）；
5. 盘面无纳甲时退回梅花用卦五行，并在 `element_source` 里写明依据；
6. 两者都取不到时留空并写清「盘面缺少用神定位依据」，不猜一个五行。

### 旺衰（WF-WANGSHUAI-001）

以用神五行与月令地支五行的生克定五档，全部走 `app/common/five_elements` 的唯一真源：

- 同气 → 旺；月令生用神 → 相；用神生月令 → 休；月令克用神 → 囚；用神克月令 → 死。

日辰只作为后置参考写入判断链，不参与分档。

### 吉凶等级（WF-FORTUNE-001）

| 信号 | 加分 |
| --- | --- |
| 用神旺/相 | +2 |
| 用神囚/死 | -2 |
| 用神休或平 | 0 |
| 体用：用生体 | +2 |
| 体用：体克用 | +1 |
| 体用：比和 | +1 |
| 体用：体生用 | -1 |
| 体用：用克体 | -2 |

合计分数 ≥3 大吉，1~2 小吉，0 平，-1 小凶，≤-2 大凶。
`step6` 输出 `fortune_score` 与 `fortune_basis`，每条依据都能对上本规则的条目。

### 应期（WF-TIMING-001）

1. 动爻地支取六爻纳甲爻表中 `is_moving` 的 `najia_branch`；
2. 以动爻逢值日、逢冲日为近期应期，逢合日提示牵连；
3. 按 `EARTHLY_BRANCHES` 顺序算出距今日数；
4. 月令只给「本月内是否得令」的粗粒度结论，不伪造具体节气日期；
5. 输出统一带免责说明：应期是可参考的时间窗口，受人为决策影响。

## 与产品边界的关系

README 声明「本系统不生成自动吉凶总分」。本决策保留 5 档吉凶，但：

- 吉凶是**规则化的等级**，不是黑箱总分，`fortune_basis` 逐条可查；
- `rule_ids` 出现在 step4、step6 输出里，可回溯到本文件；
- 免责说明固定随 step7 一起返回。

如果后续要彻底去掉吉凶等级，只需删除 `WF-FORTUNE-001` 与 step6 的打分块，
`step4` 的旺衰与生克链条不受影响。

## 后果

- 编排层结果首次具备可追溯的规则标识；
- 用神五行错误从「静默错值」变为「有依据且有出处」；
- 规则条目仍需专家签署，`status` 先给 `draft`。
