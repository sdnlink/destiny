# ADR-001：内部语料基础设施

> 状态：已采用  
> 日期：2026-08-15  
> 范围：数据分析和语料检索阶段，不决定完整业务后端技术栈

## 背景

项目已有1524本经过完整性验证的文本缓存，需要作为内部学习和检索语料。正式业务后端、身份服务和事务数据库技术栈尚未确定，但语料处理应先可复现、可查询、可审计。

## 决策

- 使用Python标准库实现离线验证、分析、无损分块和内部只读API。
- 使用ClickHouse保存文档、文本块和导入运行。
- 使用确定性子串检索作为第一阶段搜索能力。
- 每个文本块保存文档ID、块ID、字符偏移、文档哈希、块哈希和来源。
- API默认只绑定回环地址，非回环地址必须配置Bearer Token。
- 语料使用范围固定标记为 `internal_research`。
- 不在该阶段调用外部模型、外部嵌入服务或上传全文。

## 原因

- 当前仓库已使用Python完成缓存和验证，可复用经过测试的数据链路。
- Python标准库避免在Python 3.7环境中引入不稳定或不兼容依赖。
- ClickHouse适合批量文本块、统计和全文子串候选检索。
- 确定性分块和检索易于验证，适合后续建立专家标注和评测基线。
- 该方案不提前锁定未来PostgreSQL事务服务的语言和框架。

## 结果

正面结果：

- 全部语料可以通过一条命令构建和导入。
- 分块可以无损重建原文。
- 搜索结果带有来源和字符位置。
- 未来可以在不改变原始语料层的情况下增加向量索引。

限制：

- Python 3.7已经停止官方维护，当前服务只作为本地开发基础，生产化前需要升级运行时。
- 标准库HTTP服务不替代正式API网关、身份认证和限流系统。
- 子串检索不能解决异体字、同义词和语义召回。
- ClickHouse不是用户、权限和专家审核工作流的事务数据库。

## 替代方案

- 直接使用外部大模型或向量服务：因许可、隐私和可追溯风险暂不采用。
- 立即建设完整微服务：当前团队边界和技术决策未定，复杂度过高。
- 只保留文本文件：无法支持统一查询、版本运行和后续标注分析。

## 后续条件

生产部署前必须升级Python版本或将API迁移到正式业务栈，接入身份认证、TLS、审计和授权片段控制。该ADR不代表语料获得对外再发布许可。
