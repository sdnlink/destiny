# 产品与交互设计

> 状态：评审稿  
> 范围：MVP，包括公共历法底座、周易、梅花易数、模块对照和基础报告

## 1. 设计目标

产品界面首先服务于重复排盘和专业复核，其次才是知识阅读。核心页面需要让用户快速确认输入是否正确、计算经过哪些步骤、结论依据是什么，以及不同体系在哪里一致或冲突。

设计遵循以下原则：

- 输入优先：时间、地点、流派等决定计算结果的字段始终可见。
- 盘与解释分层：原始排盘不被自然语言结论遮挡。
- 证据可展开：每项判断可查看规则编号、来源和中间值。
- 专业与简明并存：默认提供摘要，专业用户可展开全部计算。
- 不制造确定性：不显示虚假的准确率、概率和绝对吉凶。
- 错误可恢复：输入错误、计算失败和报告失败均保留用户已填写内容。

## 2. MVP信息架构

```text
工作台
├── 新建推演
│   ├── 选择场景与体系
│   ├── 录入人物/事项
│   ├── 校验时间与地点
│   └── 确认并计算
├── 案例库
│   ├── 人物档案
│   ├── 事项档案
│   └── 推演记录
├── 推演结果
│   ├── 输入摘要
│   ├── 周易
│   ├── 梅花易数
│   ├── 对照分析
│   └── 报告
├── 知识库
│   ├── 术语
│   ├── 卦与爻
│   └── 来源
└── 账户
    ├── 个人资料
    ├── 隐私与数据
    └── 安全设置
```

专业后台与普通用户前台分开，不在同一导航中混合。后台包括规则、来源、案例、审核、发布和审计。

## 3. 角色任务

### 3.1 普通用户

- 快速创建一次推演，不需要理解所有高级参数。
- 清楚知道系统采用的时间、地点和计算规则。
- 阅读简明结果，需要时展开术语和依据。
- 保存、查找、导出和删除自己的记录。

### 3.2 专业用户

- 创建并复用人物档案和事项模板。
- 明确选择流派、时间边界和起卦方式。
- 查看全部中间计算值和规则版本。
- 对比不同案例、规则版本或推演体系。
- 生成带有个人或机构样式的报告。

### 3.3 术数专家

- 查看待审核规则和关联原文。
- 使用标准案例验证规则。
- 查看新旧版本结果差异。
- 批准、退回或废止规则，并填写理由。

## 4. 核心对象

| 对象 | 含义 | 主要关系 |
| --- | --- | --- |
| 人物档案 | 可复用的人物基础信息 | 可关联多个事项和推演 |
| 事项档案 | 一次问题或研究主题 | 可产生多个推演版本 |
| 推演任务 | 固定输入和规则版本的一次计算 | 产生一个或多个模块结果 |
| 模块结果 | 某个术数体系的独立结果 | 包含排盘、证据和判断 |
| 对照结果 | 多模块的一致、互补和冲突关系 | 引用模块结果，不覆盖原结果 |
| 报告 | 对某次推演结果的固定快照 | 可导出、分享和撤销 |

推演任务一旦完成，其原始输入和规则版本不可原地修改。用户修正输入时，应复制形成新任务，并保留新旧关联。

## 5. 新建推演流程

### 5.1 步骤一：选择场景

首期场景：

- 综合事项：同时使用已支持的多个模块。
- 周易起卦：只运行周易模块。
- 梅花易数：只运行梅花易数模块。
- 研究模式：允许设置高级规则并显示全部中间值。

页面字段：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 场景 | 是 | 决定默认模块和后续字段 |
| 事项分类 | 是 | 事业、关系、财务、出行、其他等受控枚举 |
| 问题摘要 | 是 | 简洁描述，不用于决定排盘结果 |
| 关联人物 | 否 | 可选择已有档案或新建 |
| 标签 | 否 | 用于个人检索 |

不允许仅根据用户问题文本自动猜测并静默切换流派。系统可以推荐，但必须由用户确认。

### 5.2 步骤二：时间与地点

| 字段 | 必填 | 默认 | 校验 |
| --- | --- | --- | --- |
| 原始日期时间 | 是 | 当前时间 | 必须包含年月日时分 |
| 时区 | 是 | 根据地点建议 | 显示UTC偏移和历史夏令时 |
| 地点 | 条件必填 | 无 | 真太阳时启用时必须有经度 |
| 经度、纬度 | 条件必填 | 地理编码结果 | 用户可手工修正 |
| 真太阳时 | 是 | 按项目决策 | 显示修正前后时间 |
| 换日规则 | 专业模式必填 | 系统默认 | 变更时提示可能影响结果 |

确认区同时展示原始时间、标准时间、真太阳时、节气位置及干支结果。用户必须先确认，系统才创建正式推演任务。

### 5.3 步骤三：模块参数

周易参数：起卦方式、六爻值或输入数字、动爻处理规则、流派版本。

梅花参数：时间或数字起卦、数值、取数规则、体用规则、流派版本。

普通模式只显示必要字段和当前默认规则摘要；研究模式展示完整参数。高级参数一旦偏离默认值，应持续显示“自定义规则”标识。

### 5.4 步骤四：确认与计算

确认页分为四组：事项、人物、时间地点、模块规则。每组均有返回修改入口。

用户点击计算后：

1. 前端先提交输入快照。
2. 服务端再次校验所有枚举和规则版本。
3. 创建推演任务并返回任务编号。
4. 前端进入结果骨架页，按模块显示状态。
5. 模块完成后逐个显示，综合对照最后生成。

重复点击不得创建多个任务；前端使用幂等键，服务端按用户与幂等键去重。

## 6. 推演结果页

### 6.1 页面结构

结果页采用标签页或左侧紧凑导航：

- 总览
- 输入与历法
- 周易
- 梅花易数
- 对照分析
- 报告

页面顶部固定显示案例名称、任务状态、计算时间和规则版本摘要，不使用大型宣传式标题。

### 6.2 总览

总览包括：

- 输入完整度及异常提醒。
- 每个模块的核心盘面缩略视图。
- 各分析维度的摘要。
- 一致结论、互补结论和冲突结论数量。
- 尚未审核或数据不足的明显标识。

总览不直接显示一个合成的“总分”。如果后续批准自动加权，也必须显示权重来源和参与模块。

### 6.3 输入与历法

展示原始输入和所有时间转换：

- 原始本地时间和时区。
- UTC时间。
- 经度及真太阳时修正量。
- 修正后时间。
- 前后节气及交节时刻。
- 年月日时干支。
- 换年、换月和换日规则。

每个派生值支持查看算法版本，不允许只显示最终四柱而隐藏转换过程。

### 6.4 单模块结果

单模块页面固定分为三层：

1. **盘面事实**：本卦、动爻、互卦、变卦或其他结构化结果。
2. **规则判断**：体用、生克、旺衰、事项映射等证据。
3. **解释文本**：由已审核规则和证据组织出的可读说明。

规则证据展开后显示规则编号、规则名称、适用条件、实际输入值、结论、来源和版本。

### 6.5 对照分析

对照页按“分析维度 × 时间范围”组织结果，而不是把不同模块文本简单拼接。

| 状态 | 展示方式 |
| --- | --- |
| 一致 | 并列显示支持模块和各自证据 |
| 互补 | 说明不同模块观察的是不同阶段或侧面 |
| 冲突 | 显示相反判断、适用范围和数据限制 |
| 不可比较 | 说明维度或时间范围不一致 |
| 数据不足 | 明确缺少的输入，不生成补偿性判断 |

### 6.6 结果状态

| 状态 | 用户可见信息 | 可执行操作 |
| --- | --- | --- |
| 等待计算 | 排队状态和创建时间 | 取消 |
| 计算中 | 已完成模块和当前步骤 | 离开页面后后台继续 |
| 部分完成 | 成功模块及失败原因 | 重试失败模块 |
| 已完成 | 完整结果和版本 | 报告、复制、对比 |
| 规则已下线 | 历史结果仍可查看 | 使用新版本重新计算 |
| 输入已删除 | 仅保留合规所需最小审计信息 | 不可重新计算 |

## 7. 案例库

案例列表默认采用紧凑表格，字段包括名称、事项类别、关联人物、模块、创建时间、任务状态和标签。支持搜索、筛选、排序、批量归档，不使用大面积卡片布局。

案例详情展示所有推演版本及其差异。复制案例时默认复制输入，但不复制旧任务编号、旧结果和报告分享设置。

删除分两步：先进入回收状态，超过恢复期后执行彻底删除。立即删除敏感数据的请求不受普通恢复期限制。

## 8. 报告设计

### 8.1 报告类型

- 摘要报告：面向个人用户，保留核心盘面、结论和限制。
- 专业报告：包含全部输入、计算步骤、规则引用和版本。
- 对比报告：比较同一案例不同任务或规则版本。

### 8.2 报告组成

1. 报告编号、生成时间和版本。
2. 用户选择公开的输入摘要。
3. 历法与排盘基础。
4. 各模块独立结果。
5. 对照分析和冲突说明。
6. 规则与文献引用。
7. 数据限制、用途说明和免责声明。

报告是不可变快照。底层规则升级后旧报告不自动改变，用户可以显式生成新版本并查看差异。

### 8.3 分享控制

- 默认不公开，用户主动创建分享链接。
- 支持有效期、访问密码、隐藏人物信息和随时撤销。
- 分享页面禁止搜索引擎收录。
- 访问事件保留最小化安全日志，不记录不必要的个人信息。

## 9. 知识与术语交互

术语解释通过点击或侧边浮层打开，不打断当前排盘。内容分为定义、所属体系、不同流派差异和来源。现代解释与古籍原文使用不同视觉标签。

知识库搜索结果显示版本和来源，不把未经审核内容与已发布规则混排。内容缺少授权或审核时，仅内部可见。

## 10. 专家后台

### 10.1 规则工作台

列表字段：规则编号、体系、流派、版本、状态、负责人、案例通过率、更新时间。专家可按状态和体系筛选。

规则详情包括定义、适用条件、执行步骤、来源、标准案例、历史版本和评审记录。发布按钮仅在必填内容完整且测试通过后可用。

### 10.2 差异评审

新规则版本运行历史案例后，后台显示：

- 结果未变化的案例。
- 中间值变化但结论未变化的案例。
- 结论变化的案例。
- 计算失败的案例。

专家必须为结论变化填写接受或拒绝理由。

## 11. 表单与校验规范

- 角度统一存储为 `[0, 360)`，界面显示单位。
- 时间输入必须显示时区，不接受无时区的正式任务。
- 地点检索失败时允许输入经纬度，不允许静默使用城市中心点。
- 数字起卦字段只接受规则允许的格式。
- 规则版本已下线时不能创建新任务。
- 所有服务端错误返回可定位字段和错误编号。

校验提示放在字段附近，并保留已填写内容。技术错误信息记录到日志，不直接展示堆栈或数据库信息。

## 12. 空状态与异常状态

| 场景 | 展示内容 | 主操作 |
| --- | --- | --- |
| 无案例 | 简洁说明尚无记录 | 新建推演 |
| 无搜索结果 | 当前筛选条件 | 清除筛选 |
| 时间无法解析 | 冲突字段及原因 | 返回修正 |
| 模块计算失败 | 失败模块和错误编号 | 重试或联系支持 |
| 规则来源缺失 | 禁止生成正式结论 | 提交专家审核 |
| 报告生成失败 | 已保存的任务状态 | 重新生成 |
| 无权访问 | 不暴露资源是否存在 | 返回工作台 |

## 13. 响应式与可访问性

- 电脑端优先支持专业工作流，移动端支持新建、查看和分享。
- 盘面、表格和九宫等固定结构使用稳定尺寸和横向滚动，不挤压文字。
- 不只依靠颜色表达五行、吉凶或状态，同时使用文字和图标。
- 表单可用键盘操作，焦点顺序符合页面流程。
- 正文和控件满足基本对比度要求。
- 动态计算状态通过可访问文本通知，不频繁抢占焦点。

## 14. 埋点与产品指标

只采集改进产品所需的最小事件：

- `analysis_started`：开始新建推演。
- `input_validation_failed`：输入校验失败，仅记录字段类型和错误码。
- `calculation_submitted`：成功创建任务。
- `calculation_completed`：任务完成及耗时。
- `evidence_opened`：用户展开规则依据。
- `conflict_viewed`：用户查看冲突说明。
- `report_generated`：报告生成成功。
- `share_created`、`share_revoked`：分享创建和撤销。
- `data_deletion_requested`：用户发起删除。

埋点不得包含问题全文、出生时间、详细地址、经纬度、户型或报告正文。

## 15. 产品验收场景

MVP至少完成以下端到端验收：

1. 新用户创建人物和事项，完成周易推演并导出报告。
2. 用户使用梅花时间起卦，核对原始时间和真太阳时。
3. 用户同时运行两个模块，查看一致和冲突证据。
4. 用户修正输入，系统创建新任务并保留旧版本。
5. 规则下线后历史结果可查看，但不能使用旧规则新建任务。
6. 部分模块失败时保留成功结果，并可独立重试。
7. 用户创建限时分享、隐藏敏感信息并撤销链接。
8. 用户导出个人数据并申请删除。
9. 专家创建规则版本，运行案例、审核并发布。
10. 未通过案例回归的规则无法发布。

## 16. 待产品决策

- 首期登录方式及是否允许匿名临时推演。
- 默认是否启用真太阳时。
- 普通用户是否可以切换流派和换日规则。
- 综合页是否只做并列对照，还是提供自动加权摘要。
- 报告首期支持PDF、图片还是仅网页。
- 删除恢复期和报告分享默认有效期。
- AI解释在MVP中完全关闭、内部试用或对用户开放。
